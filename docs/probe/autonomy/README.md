## 对照：intake 独立澄清步骤

`ArkResearchPlanner.intake`（结构化输出，agent 之前单独一步）对"帮我调研一下大模型的落地情况"连跑 3 次，3 次都提了两个问题（行业 / 场景、地域）；加 10-27 那次为 4/4。

## 结论

1. 简单题直接交付、复杂题自己补证据、来源矛盾自己核对不推给用户：豆包稳定做到。"够了就停"也成立（天气题 5 次模型调用）。之前跑四章是外层流程逼的。
2. agent 在干活途中主动调 ask_user 不稳（3/7）。同一判断放在独立的 intake 步骤里很稳（4/4）。缺用户信息这类 HITL 不该押在 agent 的 ask_user 上。
3. 收尾失败（3/7）：搜索额度用尽后中间件回"Tool call limit exceeded. Do not call 'search_web' again."，豆包下一步有时返回空消息（finish_reason=tool_calls 但没有可解析的工具调用），循环结束且没有结构化答案。例 2 也遇到过同一报错但接着交了答案。rep4/rep5 加了 invalid_tool_calls 记录后没再复现，底层原因没抓到。要用代码兜：额度用尽时换成"基于已有材料提交答案"的提示，结束时没有结构化答案就强制补一次。
4. 读不读原文不稳（例 2 一次 0 篇一次 6 篇）。要不要强制读原文留到实现时定。
