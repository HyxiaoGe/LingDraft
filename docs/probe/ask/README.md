# ask_user 自然触发探针（2026-10-28）

脚本 `backend/scripts/probe_ask.py`，结果 `run1.json`。跳过 intake，直接让调研 agent（DeepSeek V4 Pro 思考 high，当前提示词）面对一个选型任务；提示里不写“请提问”，不点名工具。

任务：给内部员工上知识库问答，在「调 DeepSeek 官方 API」和「私有化部署开源 DeepSeek」之间选一个，要明确推荐。关键的用户内部约束（文档能否出网）故意不给。

| 版本 | 次数 | 途中提问 | 结果 |
|---|---|---|---|
| 缺约束，若问则答“可以出网” | 2 | 0 / 2 | 一次“明确推荐私有化”（按“内部文档天然可能敏感”猜的，补充条件里才说不敏感可选 API）；一次条件式结论 |
| 缺约束，若问则答“不能出网” | 2 | 1 / 2 | 问了的那次：问题、选项、“不问会怎样”都合格，答“不能出网”后明确推荐私有化并引用 API 协议条款；没问的那次给“默认 API，敏感则私有化”的条件式结论 |
| 缺约束，若问则跳过 | 2 | 0 / 2 | 都是条件式结论（默认 API，列出反转条件），假设里写明了默认前提 |
| 补上约束（不能出网、有 A100 和运维） | 2 | 0 / 2 | 都不问，直接推荐私有化，64 / 80 秒 |

## 判断

- 管线：真实模型的一次提问走完了中断 → 回答 → 工具结果 → 继续 → 答案用到回答的全程，在进程内（内存检查点）通过。跨进程恢复和接口 / 前端的提问卡仍只有假模型覆盖。
- 该问时问：6 次缺约束只问了 1 次。模型更倾向于“给条件式结论”而不是问，哪怕用户要的是“明确推荐”。按 Codex 的三条标准，第三条“不能合理绕过”模型自己判断为可以绕过（分情况说明）。
- 边界：5 次没问里，4 次是诚实的条件式结论并写明假设；1 次（missing_A#0）把“内部文档天然可能敏感”这个猜测写成了“明确推荐私有化”，只在补充条件里留了后路，这是 Codex 说的“猜测包装成确定答案”，整理步骤把这个前提记进了假设，但正文结论没有体现。
- 信息齐全时不问：2 / 2。
- 跳过路径没测到（跳过版本两次都没问）。

## 没定的

要不要让模型在用户明确要“推荐一个”、关键约束又缺时更倾向于问。现在的提示词“关键条件不知道又没法问时给条件式结论”可能被读成“能给条件式结论就不用问”。这是产品取舍：问得少省一张卡，但“明确推荐”就只能是条件式的。

## 第二轮（提示词按 Codex 的完成标准改后，`run2.json`）

改动：系统提示和工具描述写明“用户要的是明确选择、一项没确认的用户约束足以翻转选择时，先问；分情况说明不算完成；只有用户跳过了才按标注假设给建议”，问法要问用户知道的具体事实、一个问题一件事、选项互斥、可以带“尚不清楚”。

| 版本 | 次数 | 途中提问 | 结果 |
|---|---|---|---|
| 缺约束，答“可以出网” | 3 | 3 / 3 | 三次都明确推荐官方 API，理由都是“私有化的唯一核心优势（数据不出内网）你们不需要” |
| 缺约束，答“不能出网” | 3 | 3 / 3 | 三次都明确推荐私有化，官方 API 直接排除 |
| 补上约束 | 3 | 0 / 3 | 直接推荐私有化，97～110 秒 |

六次提问的问法都是“公司是否允许把内部文档片段发送给外部 API”，选项是允许 / 不允许 / 尚不清楚（一次多了“部分可以”），“不问会怎样”都写明“不确认就只能给条件式结论，完不成你要的明确选择”。和 Codex 示例的问法一致，没有再把“内容敏感”和“公司禁止出网”捆在一起。

判断：该问时问 6 / 6，信息齐全时不问 3 / 3，用户不同回答确实翻转了推荐。第一轮的 1 / 6 是提示词把“条件式结论”当成了可接受的绕过方式；改成“用户要明确选择时分情况不算完成”后行为稳定。耗时 77～114 秒，和不问时相当。
